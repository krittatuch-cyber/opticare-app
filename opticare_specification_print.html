OptiCare

เอกสารสรุปข้อกำหนดคุณสมบัติการทำงานและพิมพ์เขียวสถาปัตยกรรมคลาวด์เซิร์ฟเวอร์เลสสำหรับระบบจัดการร้านแว่นตาระดับพรีเมียม

ระบบคลาวด์: Cloudflare Pages & D1 Database

วันที่จัดทำ: 2 มิถุนายน 2569

สถานะเอกสาร: สมบูรณ์ (พิมพ์เขียวการใช้งาน)

1. สถาปัตยกรรมระบบ (System Architecture)

ระบบ OptiCare ถูกพัฒนาขึ้นโดยใช้เทคโนโลยีเว็บที่เป็นมาตรฐานและสถาปัตยกรรมแบบ Dual-Runtime Hybrid Architecture ซึ่งมีเป้าหมายสูงสุดเพื่อให้ตัวระบบสามารถรันได้อย่างยืดหยุ่น ทั้งบนเครื่องคอมพิวเตอร์แบบออฟไลน์ (Local) และการให้บริการบนคลาวด์เซิร์ฟเวอร์เลสแบบออนไลน์ (Cloud Production)

💡 ความเชื่อมโยงแบบ Single-Codebase

หน้าบ้าน (Frontend Client) ทั้งระบบจะใช้สคริปต์ตัวเดียวกันโดยเชื่อมโยงผ่าน API แบบสัมพัทธ์ (Relative URL) ทำให้สามารถทำงานคู่กับหลังบ้านที่เป็นเครื่องคอมพิวเตอร์ของคุณเอง หรือเชื่อมไปยังหลังบ้าน Serverless ของ Cloudflare ได้ทันทีโดยไม่ต้องแก้ไขหน้าจอ

1.1 ส่วนการแสดงผลหน้าบ้าน (Frontend Single Page Application)

  • HTML5 & CSS3 (Vanilla): ใช้โครงสร้างเว็บหน้าเดียวความเร็วสูง จัดทำระบบสไตล์ด้วย CSS variables แบบ Custom Luxury มอบประสบการณ์ตอบสนองที่ดีเยี่ยม (Responsive Design) รองรับทั้งคอมพิวเตอร์และหน้าจอมือถือ
  • Bilingual Engine (translations.js): พจนานุกรมคำแปลจัดแบ่งโครงสร้างอย่างเหมาะสม รองรับสลับภาษาไทย (TH) และภาษาอังกฤษ (EN) บนหน้าจอทั้งหมดในเศษเสี้ยววินาที
  • Analytics & Charts (Chart.js via CDN): เรียกใช้งานชุดไลบรารีสถิติยอดนิยม เพื่อใช้วาดกราฟยอดขายแบบตอบสนอง (Interactive Charts) ได้อย่างรวดเร็วและสวยงาม

1.2 ส่วนบริการ API หลังบ้าน (Backend Architectures)

สภาพแวดล้อม (Runtime) เครื่องมือ API (Server) ระบบฐานข้อมูล (Database) วัตถุประสงค์การใช้งาน
Local PC (ใช้งานในร้าน) Python 3.12 + FastAPI SQLite 3 (ไฟล์เครื่องเดี่ยว) ทดสอบระบบ หรือใช้งานแบบเครื่องเดียวที่ร้านแบบไม่ต้องใช้อินเทอร์เน็ต
Cloudflare (ออนไลน์คลาวด์) Pages Functions (JS Workers) Cloudflare D1 (คลาวด์ SQLite) ใช้งานจริง รองรับพนักงานหลายคนเปิดใช้พร้อมกันจากสาขาต่างๆ ทั่วโลก

2. ข้อกำหนดคุณสมบัติเชิงฟังก์ชันการใช้งาน (Functional Specifications)

คุณสมบัติระบบทั้ง 9 หน้าหลักมีขอบเขตการทำงานที่เชื่อมโยงถึงข้อมูลในตู้ฐานข้อมูลเดียวกันอย่างสมบูรณ์แบบ ดังนี้:

2.1 หน้า Login (Split-Screen Interface)

การเข้าสู่ระบบถูกออกแบบให้รองรับสไตล์ Clinical Luxury (ด้านซ้ายแสดงภาพคลินิกแว่นตาพรีเมียม ด้านขวาเป็นฟอร์มเข้าสู่ระบบแบบกระจกฝ้า)

  • สิทธิ์แบบ Role-based Access Control: ตัวระบบอนุญาตให้ใช้อีเมลและพาสเวิร์ดใดๆ ก็ได้เพื่อผ่านเข้าใช้งาน แต่จะมีการกำหนดสิทธิ์ (Permissions) โดยอัตโนมัติตามรูปแบบอีเมล:
  • Store Manager (Admin): อีเมลประกอบด้วยคำว่า admin (เช่น admin@opticare.com) -> เข้าถึงหน้าข้อมูลรายงาน วิเคราะห์การเงิน จัดการ permissions ของพนักงาน และคลังสินค้าได้ทั้งหมด
  • Optometrist (นักทัศนมาตร): อีเมลประกอบด้วยคำว่า optom -> เห็นเฉพาะหน้าตารางนัดหมาย ตารางรายชื่อลูกค้า และบันทึกประวัติค่าสายตาคนไข้
  • Receptionist (พนักงานต้อนรับ): อีเมลประกอบด้วยคำว่า recep -> ค้นหาประวัติลูกค้า ตารางนัดหมาย ขายสินค้าหน้าร้าน และปรับระดับสินค้าคงคลังได้ แต่ถูกปิดไม่ให้เห็นรายงานการเงินและพนักงาน

2.2 แดชบอร์ดสรุปผล (Dashboard & Real-time Feeds)

หน้าสรุปสถิติผลงานด่วนของสาขาที่กำลังใช้งานอยู่ ประกอบด้วยฟังก์ชันดังนี้:

  • Stats Widgets: คำนวณสรุปยอดรายรับรวมสาขา, จำนวนยอดคิวงานแล็บแว่นตาที่ค้างฝนเลนส์ และจำนวนชนิดสินค้าคงเหลือในคลังที่ต่ำกว่าเกณฑ์ขั้นต่ำ
  • Recent Orders & Lab Jobs List: แสดงตารางสรุปคำสั่งซื้อล่าสุด 5 รายการ (สามารถกดคลิกที่ชื่อลูกค้าเพื่อข้ามไปดูประวัติได้อย่างรวดเร็ว) และตารางแสดงความคืบหน้าของงานฝนเลนส์สายตาที่ต้องดำเนินการส่งมอบ
  • Low Stock warning queue: แสดงรายการป้ายแจ้งเตือนชื่อสินค้า คิวอาร์โค้ด และจำนวนคงเหลือแบบสดๆ ให้พนักงานฝ่ายจัดซื้อทำงานได้ทันที

2.3 หน้าจัดเก็บลูกค้าและระบบแจ้งเตือนเชิงรุก (Customers Directory)

ระบบรวบรวมรายชื่อลูกค้าพร้อมตัวช่วยอำนวยความสะดวกสำหรับพนักงานต้อนรับ:

  • การแจ้งเตือนตรวจสายตาประจำปี (Preventive Alerts): คำนวณวันหมดอายุของค่าวัดสายตาคนไข้ หากเกิน 1 ปี ระบบจะติดธงแถบแดงและกระดิ่งเตือนทันที
  • Filter Alert: ปุ่มกรองคัดแยกเพื่อดูเฉพาะลูกค้าที่ "ถึงกำหนดตรวจสายตาเชิงรุก" เพื่อให้ทีมงานสามารถโทรประสานเพื่อสร้างนัดหมายนัดวัดสายตาได้ง่าย
  • ฟอร์มเพิ่มลูกค้าใหม่ (Add Customer Modal): บันทึกข้อมูลประวัติเบื้องต้นลงตารางข้อมูลในคลาวด์ D1

2.4 ประวัติประวัติสายตา OD/OS (Customer Detailed Profile)

หน้ารวบรวมข้อมูลสายตาที่สำคัญที่สุดของคนไข้แต่ละราย:

  • Refraction OD/OS History Grid: แสดงตารางสรุปประวัติสายตาอย่างละเอียดของตาทั้งสองข้าง โดยแยกการดีไซน์อย่างชัดเจนเพื่อป้องกันความผิดพลาด:
    • OD (ตาขวา - แถบสีเขียวมรกต): บันทึกและแสดงค่า Sphere (สั้น/ยาว), Cylinder (เอียง), Axis (องศาเอียง), ADD (แอดดิชันสำหรับแว่นอ่านหนังสือ) และ VA (ระดับการมองเห็น)
    • OS (ตาซ้าย - แถบสีทองแชมเปญ): บันทึกและแสดงค่า SPH, CYL, AXIS, ADD, และ VA
  • บันทึกค่าสายตาใหม่ (Log New Exam): หน้าต่างฟอร์มรับข้อมูลวัดสายตาล่าสุด เมื่อกดบันทึก จะทำการอัปเดตประวัติการวัดล่าสุด และเลื่อนวันกำหนดตรวจครั้งถัดไปล่วงหน้าไปอีก 365 วัน (1 ปี) ให้โดยอัตโนมัติ
  • Purchase History Logs: ตารางประวัติช้อปปิ้ง บันทึกค่าใช้จ่าย ยอดมัดจำ และยอดค้างจ่ายทั้งหมดที่ผูกกับชื่อลูกค้าคนดังกล่าว

2.5 สินค้าคงคลังและการปรับระดับแบบเรียลไทม์ (Inventory Management)

  • การแบ่งหมวดสินค้า: แยกปุ่มกดกรองข้อมูลคลังแว่นตาออกเป็น 3 หมวดหมู่ชัดเจน ได้แก่ กรอบแว่นแบรนด์เนม (Frames), เลนส์สายตาแล็บ (Lenses) และคอนแทคเลนส์ (Contact Lenses)
  • ระบบป้ายสต็อกฉุกเฉิน (Low Stock Alert): ขึ้นสัญลักษณ์เตือนสินค้าขาดคลัง เพื่อความสะดวกในการตรวจสอบชิ้นส่วน
  • ปรับระดับคลังสินค้า (Adjust Stock): กล่องโมดอลให้ผู้มีสิทธิ์ปรับเพิ่ม/ลดตัวเลขสต็อกสินค้าคงเหลือลงฐานข้อมูล D1 ได้โดยตรง

2.6 ระบบจุดขาย มัดจำ และ พิมพ์ใบเสร็จ (POS Engine & Deposits)

ระบบการชำระเงินที่ได้รับการออกแบบมาอย่างยอดเยี่ยมเพื่ออำนวยความสะดวกในกระบวนการหน้าร้านแว่นตา:

  • ผูกบัญชีคนไข้: สามารถสืบค้นรายชื่อสมาชิกเพื่อตัดแต้มหรือบันทึกประวัติการสั่งประกอบแว่นตา หรือคลิกเลือกประเภทลูกค้าทั่วไปแบบ Walk-in
  • ระบบบวกราคาตะกร้าและส่วนลดพิเศษ: คำนวณราคาหักลบด้วยส่วนลดพิเศษ (Discount) ในระดับบาท
  • ระบบการชำระเงินมัดจำ (Deposit down-payment): เนื่องจากกรอบแว่นและเลนส์บางคู่ต้องส่งประกอบแล็บ ระบบจึงอนุญาตให้กรอกยอดชำระมัดจำ และระบบจะคำนวณยอดค้างจ่าย (Balance Due) ให้อัตโนมัติ เพื่อคอยเก็บตกเงินส่วนที่เหลือตอนส่งมอบแว่นตา
  • ระบบแบ่งช่องทางชำระเงิน (Split Payment Engine): สนับสนุนการชำระเงินมัดจำแบบแยกช่องทาง เช่น "จ่ายเงินสด 500 บาท และแสกนโอนผ่านบัญชีธนาคาร 1,000 บาท" พร้อมระบบตรวจเช็คผลรวมหากพิมพ์จำนวนเงินไม่ครบ
  • พิมพ์ใบเสร็จประกอบแว่น (Receipt Print Mode): ป๊อปอัปพรีวิวใบเสร็จความร้อนขนาด 80mm สำหรับสั่งพิมพ์แสดงรายละเอียดบิล ยอดมัดจำ ยอดค้างชำระ และชื่อนักทัศนมาตรที่ทำการวัดสายตา

2.7 ตารางการนัดหมายประจำสัปดาห์ (Weekly Calendar & Color-coding)

ปฏิทินแสดงรอบเวลานัดหมายแบบ 7 วันประจำสัปดาห์ที่มีการจัดแบ่งตามระบบสีการนัดพบลูกค้า:

  • สีเขียวเข้ม (Teal / Emerald): นัดหมายวัดการมองเห็น / วัดสายตา (Eye Exam)
  • สีเขียวมรกต (Mint / Emerald): นัดหมายส่งมอบแว่นตา / รับแว่นตา (Pick-up)
  • สีน้ำเงินคลิกนิก (Clinic Blue): นัดหมายพบปะ / ปรึกษาปัญหาสายตา (Consultation)
  • Add Appointment Modal: บันทึกจัดตารางเวลานัดหมายกับลูกค้าลงคลาวด์ D1

2.8 การคุมสิทธิ์พนักงาน (Staff Permissions Matrix)

ระบบแสดงบุคลากรและแถบกำหนดสิทธิ์เข้าใช้เมนูระบบโดยตรง:

  • การปรับเปลี่ยนบทบาท: เปลี่ยน Role พนักงานได้เรียลไทม์ (Admin, Optometrist, Receptionist)
  • สลับสิทธิ์การเข้าถึงเมนู: ปลดล็อกหรือปิดล็อกสิทธิ์ในแต่ละแท็บเมนูพนักงานแบบรายบุคคลได้อย่างอิสระ

2.9 รายงานวิเคราะห์ผลงานสาขาเชิงธุรกิจ (Reports Analytics & Charts)

ระบบนำเข้ายอดการทำธุรกรรม POS และยอดมัดจำทั้งหมดจากฐานข้อมูลจริง มาประมวลผลวาดเป็นกราฟวิเคราะห์เชิงลึก:

  • 7-Day Combined Income (Line Chart): กราฟเส้นแสดงแนวโน้มรายรับรวมรายวันย้อนหลัง 7 วัน สำหรับใช้วิเคราะห์เงินหมุนเวียน
  • Sales Breakdown (Doughnut Chart): กราฟวงกลมแยกหมวดความนิยมของประเภทสินค้าแว่นตา (กรอบ / เลนส์ / คอนแทค)
  • Branch Revenue Comparison (Bar Chart): กราฟแท่งเปรียบเทียบยอดขายรวมจริงของแต่ละสาขาในเครือร้านแว่น

3. พิมพ์เขียวสำหรับการพัฒนาและต่อยอดระบบในอนาคต

สำหรับนักพัฒนาที่สนใจนำโครงสร้างระบบ OptiCare ไปขยายฟังก์ชันหรือต่อยอดขีดความสามารถ แนะนำจุดตั้งต้นสำคัญดังนี้:

3.1 โครงสร้างตารางและ SQL คิวรี (D1 SQL schema)

โครงสร้างฐานข้อมูล SQLite คลาวด์ถูกรวมไว้ที่ไฟล์ schema.sql ซึ่งเป็นสคริปต์แบบอนุกรมดั้งเดิม ทำให้ผู้พัฒนาสามารถเพิ่มเติมตาราง เช่น ตารางเก็บบันทึกข้อมูลคูปองส่วนลดสมาชิก (Coupons) หรือตารางค่าสายตาเฉพาะรูปแบบเลนส์โปรเกรสซีฟได้อย่างง่ายดายผ่านการรันใน Cloudflare D1 SQL Console

3.2 โครงสร้างบริการ API (functions/api/[[path]].js)

เซิร์ฟเวอร์เลส API บน Cloudflare ถูกออกแบบไว้ในรูปของ Single-file REST API Router ซึ่งรับคำขอยิงแบบสัมพัทธ์ (Relative URL) ตัวระบบจัดการการคิวรีข้อมูล D1 ด้วยโครงสร้าง JavaScript Promises ที่มีความเร็วสูง นักพัฒนาสามารถขยาย API ไปยังระบบภายนอกได้ง่าย เช่น การยิงข้อมูลหลังชำระเงิน POS หรือส่งประวัติวัดสายตาไปยัง LINE Notify API เพื่อแจ้งเตือนคนไข้ผ่านไลน์ส่วนตัวได้ด้วยโค้ด JavaScript เพียงไม่กี่บรรทัด

3.3 การจัดแต่งสไตล์โครงสร้าง CSS (style.css)

ชุดจัดระเบียบสไตล์ทั้งหมดถูกคุมด้วย CSS Variables ที่มีศูนย์กลางอยู่ที่ต้นไฟล์ :root และ body.dark-theme หากทางร้านแว่นตาต้องการรีแบรนด์สีสัน (เช่น เปลี่ยนจากโทนมรกต-ทองหรูหรา ไปเป็นสีดำลึกลับและขอบทองคำเงาวับ) นักพัฒนาเพียงแก้รหัสค่าสีที่ต้นไฟล์เพียงจุดเดียว สีในทุกหน้าของระบบจะผันตามอัตโนมัติอย่างสวยงาม
